Théorie

Notes essentielles

Cette page regroupe les notions théoriques importantes rencontrées pendant le laboratoire. Elle ne reprend pas toutes les manipulations pas à pas, mais explique les concepts nécessaires pour comprendre le fonctionnement global du projet.

Les éléments en vert correspondent aux champs, opérateurs ou actions réellement utilisés pendant le labo. Les éléments en gris représentent des possibilités présentes dans Cloudflare, mais non utilisées dans cette réalisation.

01 / Reverse Proxy

Un reverse proxy est un serveur intermédiaire placé devant le serveur réel. Dans ce labo, Cloudflare reçoit les requêtes des visiteurs avant de les transmettre à GitHub Pages.

Cela permet d’ajouter une couche de contrôle entre le client et l’hébergement : filtrage, HTTPS, cache, redirections et règles WAF.

02 / DNS & Nameservers

Le DNS permet de transformer un nom de domaine lisible en destination technique. Les nameservers indiquent quel service est responsable de la zone DNS du domaine.

En remplaçant les nameservers Namecheap par ceux de Cloudflare, Cloudflare devient responsable de la résolution DNS du domaine.

03 / CNAME

Un CNAME est un alias DNS. Il permet de faire pointer un nom de domaine ou un sous-domaine vers un autre nom de domaine.

Dans ce projet, les CNAME permettent de faire pointer le domaine personnalisé vers regalia00.github.io, qui correspond à GitHub Pages.

04 / Proxy Status

État Compréhension
Nuage orange Cloudflare agit comme reverse proxy et peut appliquer les règles WAF.
Nuage gris Cloudflare gère seulement le DNS, sans filtrer le trafic HTTP/HTTPS.

Le nuage orange est indispensable pour que le WAF puisse agir.

05 / HTTPS & SSL/TLS

HTTPS chiffre les échanges entre le navigateur et le site. Le protocole SSL/TLS garantit la confidentialité et l’intégrité des données échangées.

Cloudflare facilite cette partie en fournissant une couche HTTPS visible par le cadenas dans le navigateur.

06 / Fonctionnement général d’une règle WAF

Une règle WAF Cloudflare suit une logique conditionnelle simple : 

SI condition vraie
ALORS appliquer action

Une condition est construite à partir d’un champ, d’un opérateur et d’une valeur. Plusieurs conditions peuvent être combinées avec AND, OR ou NOT.

Élément Rôle Exemple
Champ Information analysée dans la requête URI Path, Country, Cookie
Opérateur Façon de comparer la valeur equals, contains, does not contain
Action Réaction appliquée par Cloudflare Block, Managed Challenge
Logique Combinaison de conditions AND / OR / NOT

07 / Champs disponibles dans Cloudflare WAF

Champ Utilisé Rôle
URI Path ✓ Filtrer une page précise, par exemple /page2.html.
Country ✓ Filtrer selon le pays d’origine de l’adresse IP.
User-Agent ✓ Identifier le navigateur ou certains outils automatisés.
Cookie ✓ Filtrer selon une valeur envoyée par le navigateur.
IP Source Address ✗ Filtrer une adresse IP précise ou une plage IP.
Hostname ✗ Cibler un domaine ou un sous-domaine précis.
HTTP Method ✗ Filtrer selon GET, POST, PUT, DELETE, etc.
Referer ✗ Analyser la page d’origine ayant envoyé le visiteur.
Query String ✗ Filtrer selon les paramètres de l’URL, par exemple ?id=1.
Headers HTTP ✗ Analyser d’autres en-têtes envoyés par le navigateur.
ASN ✗ Filtrer selon le fournisseur réseau ou l’opérateur Internet.
Bot Score ✗ Évaluer la probabilité qu’une requête provienne d’un bot.
JA3 / TLS Fingerprint ✗ Identifier une empreinte TLS du client.

Les champs utilisés dans le labo sont suffisants pour comprendre les bases du filtrage applicatif : URL, pays, navigateur et cookie.

08 / Opérateurs disponibles

Opérateur Utilisé Fonction
equals ✓ La valeur doit être exactement identique.
contains ✓ La valeur doit contenir un texte précis.
does not contain ✓ La valeur ne doit pas contenir un texte précis.
does not equal ✗ La valeur doit être différente.
starts with ✗ La valeur commence par un texte donné.
ends with ✗ La valeur finit par un texte donné.
matches regex ✗ La valeur correspond à une expression régulière.
in ✗ La valeur appartient à une liste définie.
greater than / less than ✗ Comparer des valeurs numériques.

09 / Actions Cloudflare

Action Utilisé Effet
Block ✓ Bloque immédiatement l’accès à la ressource.
Managed Challenge ✓ Demande une vérification gérée automatiquement par Cloudflare.
Allow ✗ Autorise explicitement une requête.

10 / Règles réellement créées pendant le labo

Objectif Condition Action
Bloquer une page URI Path equals /page2.html Block
Geoblocking Country equals United States AND URI Path equals /page1.html Block
Bloquer Chrome User-Agent contains Chrome Block
Challenge Chrome belge Country equals Belgium AND User-Agent contains Chrome AND URI Path equals /page2.html Managed Challenge
Filtrage cookie URI Path equals /page2.html AND NOT Cookie contains superadmin=yes Block

Ces règles montrent l’usage des principales possibilités du WAF : filtrage par URL, géolocalisation IP, navigateur, challenge et cookie.

11 / Cookies

Un cookie est une donnée stockée côté navigateur et envoyée automatiquement dans les requêtes HTTP. Il peut contenir une valeur servant à identifier une session ou un rôle.

Dans le labo, le cookie superadmin=yes a été créé manuellement avec JavaScript via les Developer Tools.

Un cookie créé côté client peut être falsifié. Dans un vrai site, il doit être généré et signé par le serveur.

12 / Redirections HTTP

Une redirection HTTP indique au navigateur qu’il doit aller vers une autre URL. Cloudflare peut générer cette redirection avant que la requête n’atteigne GitHub Pages.

Dans le labo, les redirections permanentes utilisent le code HTTP 301 et le header Location.

13 / DNS ≠ Redirection

Le DNS sert à indiquer vers quel service envoyer une requête. Une redirection HTTP, elle, indique au navigateur de changer d’URL.

Élément Rôle
DNS Résout un nom de domaine vers une destination.
Redirection Renvoie le navigateur vers une autre URL.

Ce qu’il faut retenir

DNS

Le domaine doit savoir vers qui diriger le trafic.

Proxy

Cloudflare se place devant le site réel.

WAF

Les règles filtrent les requêtes avant l’hébergement.

Cookies

Ils peuvent être utilisés pour créer des règles d’accès.

Redirection

Cloudflare peut renvoyer une URL vers une autre destination.

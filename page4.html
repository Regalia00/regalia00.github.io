Notes techniques

Retour d’expérience

Cette page sert de carnet technique pour garder une trace des problèmes rencontrés, des tests réalisés et des solutions trouvées pendant le laboratoire.

L’objectif est surtout de comprendre les erreurs et les comportements du réseau plutôt que simplement suivre un tutoriel sans analyser ce qui se passe.

01 / Propagation DNS

Problème observé :

Après le changement des nameservers vers Cloudflare, le domaine ne répondait pas immédiatement. Certaines requêtes utilisaient encore les anciens DNS.

Compréhension :

Les serveurs DNS gardent des informations en cache pendant un certain temps. La propagation peut donc prendre plusieurs minutes ou plusieurs heures.

02 / HTTPS non actif

Problème observé :

Le site fonctionnait mais sans cadenas HTTPS juste après l’ajout du domaine personnalisé.

Compréhension :

Cloudflare et GitHub doivent générer les certificats SSL/TLS. Cette étape demande parfois un délai avant l’activation complète.

03 / Mauvaise configuration DNS

Problème observé :

Une erreur de configuration CNAME empêchait le domaine de pointer correctement vers le site.

Compréhension :

Le DNS doit rester cohérent entre Cloudflare et GitHub Pages. Une petite erreur dans les records peut empêcher le chargement du site.

04 / Compréhension du Reverse Proxy

Point important :

Au début, il était difficile de visualiser le rôle exact du reverse proxy dans le projet.

Compréhension :

Le reverse proxy agit comme une couche intermédiaire entre le visiteur et l’hébergement. Cela permet à Cloudflare de filtrer, protéger et analyser le trafic avant qu’il atteigne GitHub Pages.

05 / Tests WAF

Plusieurs règles ont été testées afin de comprendre comment Cloudflare réagit selon les conditions.

  • Blocage par URI Path
  • Filtrage User-Agent
  • Challenge CAPTCHA
  • Blocage par pays

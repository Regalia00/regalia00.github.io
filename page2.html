Projet

Plan du labo

Cette page explique ce qui va être réalisé dans le projet et surtout ce que chaque partie doit permettre de comprendre. Le but n’est pas seulement de construire un site, mais de voir comment plusieurs services travaillent ensemble pour rendre ce site accessible, propre et plus sécurisé.

Le projet est découpé en plusieurs blocs : le domaine, le DNS, l’hébergement, Cloudflare, le reverse proxy et le WAF. Chaque bloc a son importance dans le résultat final.

01 / Finalité du projet

La finalité est de mettre en place un site web public accessible avec un nom de domaine personnalisé, puis de le faire passer par Cloudflare avant qu’il atteigne l’hébergement réel.

Ce montage permet de comprendre une idée importante : un site visible sur Internet n’est pas forcément contacté directement. Il peut être protégé par une couche intermédiaire qui analyse et contrôle le trafic.

02 / Achat du nom de domaine

Le nom de domaine est le point d’entrée du projet. Sans lui, le site reste accessible via une adresse technique peu lisible. Avec un domaine, on obtient une adresse plus claire et plus professionnelle.

  • Comprendre le rôle d’un domaine
  • Relier un nom humain à un service web
  • Préparer la gestion DNS via Cloudflare

03 / Gestion DNS

Le DNS sert à faire le lien entre le nom de domaine et la destination du trafic. Dans le projet, Cloudflare devient le gestionnaire DNS principal grâce au changement des nameservers.

Cette partie permet de comprendre que le DNS agit comme une sorte d’annuaire d’Internet.

04 / Hébergement du site

Le site est hébergé comme un site statique. Cela signifie qu’il contient principalement des fichiers HTML, CSS et éventuellement JavaScript, sans base de données ni backend complexe.

  • Créer les pages du site
  • Comprendre GitHub Pages
  • Publier des fichiers web sur Internet

05 / Cloudflare

Cloudflare est la couche placée devant le site. Son intérêt est de centraliser plusieurs fonctions importantes : DNS, HTTPS, protection, cache et filtrage.

Dans le projet, Cloudflare permet surtout de comprendre comment un service externe peut protéger un site sans modifier directement les fichiers hébergés.

06 / Proxy & Reverse Proxy

Un proxy classique agit souvent pour le client, alors qu’un reverse proxy agit devant le serveur. Ici, Cloudflare reçoit les requêtes des visiteurs avant de les transmettre au site hébergé.

C’est cette logique qui rend le reverse proxy intéressant : il devient un point de passage obligatoire, donc un point de contrôle.

07 / HTTPS & certificats

Le HTTPS permet de chiffrer les échanges entre le navigateur et le site. Dans le projet, cette partie permet de comprendre pourquoi un cadenas apparaît dans le navigateur et pourquoi les certificats sont importants.

La sécurité ne se voit pas toujours, mais elle change la manière dont les données circulent.

08 / WAF et règles de sécurité

Le WAF permet de créer des règles pour contrôler l’accès au site. On peut par exemple bloquer une page précise, filtrer selon un pays, un navigateur, une IP ou certains comportements.

Cette partie montre que le reverse proxy ne sert pas seulement à rediriger le trafic : il peut aussi devenir une vraie couche de sécurité.

Progression logique du projet

01 / Domaine

Obtenir une adresse publique claire pour le site.

02 / DNS

Comprendre comment le domaine dirige le trafic.

03 / Hébergement

Publier les pages web avec un hébergement statique.

04 / Reverse Proxy

Faire passer les visiteurs par Cloudflare avant le site.

05 / Sécurité

Ajouter HTTPS, filtrage et règles WAF.

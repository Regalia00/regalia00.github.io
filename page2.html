Projet

Projet réalisé

Cette page présente les grandes étapes concrètes du projet réalisé pendant le laboratoire. L’objectif était de construire un site web statique, de l’associer à un nom de domaine personnalisé, puis de le protéger avec Cloudflare.

Le projet a permis de manipuler plusieurs éléments essentiels d’une infrastructure web : nom de domaine, DNS, GitHub Pages, reverse proxy, HTTPS, WAF, cookies et redirections.

01 / Finalité du projet

La finalité était de rendre le site accessible via le domaine www.thibault-esr-itscm.xyz, tout en faisant passer le trafic par Cloudflare avant d’atteindre l’hébergement GitHub Pages.

Ce montage permet de comprendre qu’un site web public peut être protégé par une couche intermédiaire qui inspecte, filtre et redirige les requêtes.

02 / Nom de domaine

Le domaine thibault-esr-itscm.xyz a été acheté sur Namecheap. Le service proposé initialement dans le labo n’étant pas utilisable, Namecheap a servi d’alternative pour obtenir rapidement un domaine fonctionnel.

  • Achat du domaine
  • Validation ICANN par email
  • Désactivation du renouvellement automatique

03 / Gestion DNS

Après l’ajout du domaine dans Cloudflare, les nameservers Cloudflare ont été configurés chez Namecheap. Cloudflare est ainsi devenu responsable de la zone DNS.

  • Nameservers : conrad.ns.cloudflare.com et lorna.ns.cloudflare.com
  • Vérification avec nslookup
  • Création des enregistrements CNAME

04 / Hébergement GitHub Pages

Le site a été hébergé avec GitHub Pages à partir du repository regalia00.github.io. Les pages HTML ont été créées et modifiées localement, puis envoyées vers GitHub.

  • Création du fichier index.html
  • Création de pages supplémentaires
  • Activation de GitHub Pages

05 / Connexion domaine - GitHub

Des enregistrements CNAME ont été créés dans Cloudflare afin de relier le domaine personnalisé à GitHub Pages.

  • CNAME www vers regalia00.github.io
  • CNAME racine vers regalia00.github.io
  • Configuration du custom domain dans GitHub Pages

06 / Reverse Proxy Cloudflare

Le proxy Cloudflare a été activé grâce au mode Proxied représenté par le nuage orange. À partir de ce moment, Cloudflare intercepte les requêtes avant GitHub Pages.

Cela permet d’utiliser HTTPS, le cache, les règles WAF et les règles de redirection.

07 / Règles WAF réalisées

Plusieurs règles de sécurité ont été créées pour répondre aux consignes du labo.

  • Blocage de page2.html
  • Blocage de page1.html pour les IP américaines
  • Blocage des navigateurs basés sur Chrome
  • Challenge pour les utilisateurs belges avec Chrome
  • Filtrage par cookie superadmin=yes

08 / Redirections

Des règles de redirection ont été configurées pour rediriger une page fictive vers un site externe, puis pour rediriger les sous-domaines xyz et xena vers le sous-domaine www.

L’URI a été conservée pendant la redirection afin que xena.thibault-esr-itscm.xyz/page1.html mène vers www.thibault-esr-itscm.xyz/page1.html.

Progression logique du projet

02 / DNS

Remplacement des nameservers Namecheap par ceux de Cloudflare.

Théorie

Notes essentielles

Cette page rassemble les notions théoriques importantes du laboratoire, sans refaire toutes les étapes pratiques. L’objectif est de garder les idées principales : ce que fait Cloudflare, ce qu’est un reverse proxy, pourquoi le DNS est important et comment le WAF peut contrôler l’accès au site.

Je présente ces notions avec des explications simples, comme une fiche de révision pour comprendre le fonctionnement global du labo.

01 / Reverse Proxy

Un reverse proxy est un serveur placé devant le serveur réel. Le visiteur ne contacte donc pas directement l’hébergement du site : il passe d’abord par une couche intermédiaire.

Dans ce labo, Cloudflare joue ce rôle. Cela permet de protéger le site, cacher une partie de l’infrastructure et appliquer des règles avant que la requête atteigne GitHub Pages.

02 / DNS

Le DNS permet de transformer un nom de domaine lisible en destination technique. Sans DNS, il faudrait retenir des adresses beaucoup moins pratiques.

En changeant les nameservers, on indique que Cloudflare devient responsable de la zone DNS du domaine.

03 / Proxy Status

État Compréhension
Nuage orange Cloudflare agit comme proxy et protège le trafic.
Nuage gris Cloudflare gère seulement le DNS, sans filtrer le trafic web.

Le nuage orange est donc le mode important pour profiter du reverse proxy.

04 / HTTPS & SSL/TLS

HTTPS sert à chiffrer les échanges entre le navigateur et le site. Le certificat permet au navigateur de vérifier qu’il communique avec le bon service.

Dans le labo, Cloudflare facilite cette partie en ajoutant une couche de sécurité visible par le cadenas du navigateur.

05 / Règles WAF importantes

Le WAF fonctionne avec une logique simple : si une condition correspond à la requête, alors Cloudflare applique une action. Cela permet de bloquer, autoriser ou vérifier certains visiteurs.

Champ Rôle Exemple d’utilisation
URI Path Filtrer une page précise Bloquer une page sensible
IP Source Filtrer une adresse IP Bloquer une IP abusive
Country Filtrer selon le pays Autoriser ou bloquer une zone géographique
User-Agent Identifier navigateur ou outil Détecter certains bots ou scanners
Cookie Filtrer selon une valeur stockée côté navigateur Créer une exception pour un utilisateur précis

06 / Actions possibles

Action Effet
Allow Autorise la requête.
Block Refuse directement l’accès.
Challenge Demande une vérification humaine.
JS Challenge Vérifie le comportement du navigateur.

07 / Rate Limiting

Le Rate Limiting permet de limiter le nombre de requêtes venant d’une même source pendant une période donnée.

Cette notion est utile pour comprendre comment on peut réduire les comportements abusifs, comme le flood, le spam ou certaines tentatives de brute force.

08 / Redirections

Le reverse proxy peut aussi servir à rediriger un visiteur vers une autre URL. Cela montre que Cloudflare peut agir avant même que la requête arrive sur l’hébergement.

Ce mécanisme repose notamment sur les statuts HTTP et les headers de redirection.

Ce qu’il faut retenir

DNS

Le domaine doit savoir vers qui diriger le trafic.

Proxy

Cloudflare se place devant le site réel.

WAF

Les règles filtrent les requêtes avant l’hébergement.

HTTPS

Les échanges sont chiffrés et plus sûrs.
